Tokenization是什么

发表于2025-08-25|更新于2025-08-31|LLMsTransformersTokenization
|总字数:3.6k|阅读时长:14分钟|浏览量:

对于机器学习或者深度学习的模型，都需要将文本转换为数字序列作为输入，通常需要一个合适的词表。Tokenization是将文本切分成词典中的词，从而得到用词典的index表示的数字序列。

Tokenization的发展

大概有三个阶段：词粒度、字粒度和 Subword 粒度

A. 词粒度 Word-based

每一个token是词典中的一个词

  • 对于拉丁语系很简单，按照空格和标点符号分割即可
  • 对于中文日文，则需要专门进行分词，比如中文分词一般都用jieba，哈工大的LTP等

优点：

  • 符合人类的直觉，词的含义完备
  • 对于英文来说实现很简单

缺点：

  • 如何构造一份好的词典，以及词典过大的问题
  • OOV（Out of Vocabulary）问题，对于词典中没有词一般会分配一个统一来处理，信息丢失
  • 同义词和误拼会被认为是不同的词。比如do not和don’t虽然含义一样，但是最终的id不一样。类似的还有词的不同形态，比如have, has, had, having等
  • 词典中的词没有任何关联，低频词不会得到充分的训练。比如oarfish，这个词虽然第一眼可能不知道什么意思，但是能猜出是一种鱼（皇带鱼）

B. 字粒度 Character-based

把文本按照最小粒度来拆分

  • 对于英文来说就是26个字母加上一些标点符号
  • 中文来说就是字

优点：

  • 实现简单
  • 词典很小
  • 几乎没有OOV（Out of Vocabulary）问题

缺点：

  • 对于英文来说，单个字母几乎没有含义
  • 难以学习到词汇的真正含义。由于中文的一个字还是有一定的含义，所以在中文勉强可以使用，但是英文几乎没法使用
  • 会让输入变得很长，训练和推理更慢

C. 子词粒度：Subword

Subword Tokenization 可以认为是上面两种方法的一个中间态。其设计理念为：

  1. 词典中的每一个token都有语义。
  2. 常用的词汇尽量不要分割
  3. 不常用的词汇可以拆分成常用的、有意义的字词(Subword)

优点：

  • 几乎没有OOV Out of Vocabulary）问题
  • 有泛化能力。即使训练样本中未出现的词，也能通过subword来理解，因为subword能够捕获一些语言上词根的含义
  • 词典的大小可以控制

缺点：

  • 新技术还需要一些验证和探索
  • 对英文支持很好，但是对中文来说没有起到类似英文的Subword效果。因为中文也可以进一步拆分，比如“钅” 一般都跟金属有关，“犭”一般都跟动物有关。目前的中文的处理粒度还没有这么细致

常用Tokenize方法

A. Byte-Pair Encoding (BPE)

Neural Machine Translation of Rare Words with Subword Units

BPE

核心思想在于将最常出现的子词对合并，直到词汇表达到预定的大小时停止

  1. 准备语料\(D\)，词表大小\(V\)
  2. 使用预分词器pretokenizer来完成初步的切分（pretokenizer可以是简单基于空格的，也可以是基于规则的），比如英文拆分为26个英文字母，且每个单词的结尾处添加 “</w>“进行标识
  3. 统计每个单词的频率；【到这初始化就完成了，此时的词表中全部都是单个字母】
  4. 统计所有2-gram的组合token，将词频最高的组合token添加到词表中
  5. 检测被合并的那两个token，如果某个token在整个语料中都没有再出现过，那么就从词表中移除
  6. 重复上述第4步和第5步，直到词表的数量达到预设定的大小\(V\)
  7. <得到词表之后，将词表中所有的词按照长度进行降序排列>

编码（Encode）
编码时，遍历排好序的词表，查找词表中是否有是当前单词的子字符串的子词

  • 如果有，那么这个子词就作为表示该单词的 token 之一，原单词中除去该子词之后剩余的部分继续遍历排好序的词表
  • 当所有的词表都遍历完了之后，如果依然有子字符串没有匹配上词表中的任何子词，那么就使用<\UNK>表示该部分

解码（Decode）

  • 如果 token 是以 </w> 结尾的，说明这是一个单词的结尾
  • 如果 token 不是以 </w> 结尾的，说明这个 token 需要和其后面的 token 拼接起来构成单词

整体来看，就等同于把 </w> 替换成空格之后，直接把全部 token 拼接成一个字符串。

Byte-level BPE

BPE 仍然可能有 OOV 的问题，一个巧妙的转换是将文本表示为 byte 来处理。这样就完全解决了 OOV 的问题

Byte-level BPE：基于上面的问题，就提出了另一种方案，按照 ascii 码进行拆分，这样最小单元总共就只有256个，拆分之后再使用 BPE

gpt2就是采用的这种方法
当然这样拆分之后会有很多看起来是乱码的字符存在，比如使用gpt2-xl的 tokenizer 对 你好中国 按照 ascii 码进行拆分的代码和结果如下所示（你好中国这四个汉字，每个字使用 unicode 编码之后占用3个字节，所以按照 ascii 拆分后总共12个字符）

B. Wordpiece

Wordpiece 可以看作是 BPE 的一个变体。整体流程一样，但是在选择新词的方法不同。
BPE 每次是选择词频最高的两个词的组合。而 Wordpiece 则是选择两个点互信息(PMI)最大的词

点互信息(PMI)表示两个子词之间的凝聚程度的高低

\[PMI: L(z) = L(x,y) = log{\frac{p(x,y)}{p(x)p(y)}} = log{\frac{p(z)}{p(x)p(y)}}\]

\[BPE_{next} = argmax({pair\_freq})\]

\[WordPiece_{next} = argmax\left(\frac{pair\_freq}{first\_token_\_freq * second\_token\_freq}\right)\]

C. Unigram language modeling (UniLM)

BPE/WordPiece: 字粒度 -> 合并token -> 删除被覆盖token
UniLM: 初始化一个大词表 -> 慢慢删除token（字粒度的词汇不删除）

D. Sentencepiece

Sentencepiece 主要解决多语言的问题，将输入完全认为是 unicode 编码，不需要依赖空格和jieba等进行分词这一步
