Transformers 为什么采用 QKV Attention

注意：在看下面这篇论文之前，最好熟悉一下最原始的 Bahdanau Attention(参考知乎｜详解Bahdanau Attention)，这是一切 Attention 的起点。把 Bahdanau Attention 研究明白了对于理解 Transformers 的结构有很大帮助

Transformers 的论文在 Attention 这一部分的描述并没有讲的特别细，尤其是关于 Query、Key 和 Value 的设计。

参考同期的论文《Frustratingly Short Attention Spans In Neural Language Modeling》 – Bahdanau Attention的改进

论文中认为当时的 Attention 的隐向量至少承担了3个功能：

  • 计算 attention score
  • 计算 context vector
  • 作为 hidden state 来进行 RNN 的计算

为了更好的适配任务，作者参考了 Memory Netorkds，一次输出了3个隐向量（key、value、predict）。
这3个隐向量来计算Attention：

  • key 用来计算 attention score
  • value 用来和 Atention score 相乘
  • predict 用于预测词的分布

\[ \begin{aligned} \begin{bmatrix} k_t \\ v_t\end{bmatrix} = h_t &\in \mathbb{R}^{2k} \\ M_t=\mathrm{tanh}(W^Y[k_{t-L}\cdots k_{t-1}] + (W^hk_t)1^T) &\in \mathbb{R}^{k\times L} \\ \alpha_t = \mathrm{softmax}(w^TM_t) &\in \mathbb{R}^{1\times L} \\ r_t = [v_{t-L}\cdots v_{t-1}]\alpha^T &\in \mathbb{R}^{k} \\ h_t^* = \mathrm{tanh}(W^rr_t + W^xv_t) &\in \mathbb{R}^{k} \\ \end{aligned} \]

看公式可以知道，value 在这里作用和 Transformers 中的Attention 的 value 是完全一致的。

那怎么没有 query 呢？ 实际上 query 被隐藏在了 key 之中。在Transformers之前Attention 和 RNN 依然是深度绑定的。

作者在这里用了时刻 t 的 key 向量，和时刻 t 之前的 key 向量做了 Attention，因为作者假设时刻 t 之前的 key 和 value 是 Memory。 所以 query 就是 k_t, 而 t 时刻前面的就是 key。

虽然写法不一样，但是 Transformers 的 qkv Attention 的设计和这篇论文的设计的整体框架是一样的。细微之处的不同点列举如下：

  1. Transformers 由于丢弃了 RNN，所以可以更好的并行，采用了矩阵运算的形式
  2. Transformers 采用了 dot Attention，应该是参考了 Luong Attention。(这篇文章依然采用了 Bahdanau Attention 所使用的 Addition Attention)
  3. Transformers 的 Attention 是全连接图，而这里是 causal 形式的 Attention

为什么 Attention 最后采用了 Dot Product 而不是 Addition

在 Attention 刚被提出来的时候，其实是通过 Addition 来建立关联关系的。在 Bahdanau Attention中，表示为 \[e_{ij}=V_a^T\mathrm{tanh}(W_as_{i-1}+U_ah_j)=V_a^T\mathrm{tanh}(Q+K)\]

后来，Luong Attention 对比了多种 Attention 的方式，其中就包括了 Transformers 最终采用的 dot attention，表示为： \[e_{ij}=W_Qs_{i-1}(W_Kh_j)^T=QK^T\]

论文中，Addition Attention的效果并不太好

《Attention is All your Need》论文中，作者提到：

While the two are similar in theoretical complexity, dot-product attention is much faster and more space-efficient in practice, since it can be implemented using highly optimized matrix multiplication code.

所以说无论是效果还是计算效率上，dot attention 似乎都更好一点。

Attention 为什么使用 Multi Head ?

Multi Head Attention 最早出现在论文 《A STRUCTURED SELF-ATTENTIVE SENTENCE EMBEDDING》，用来做表示学习

作者参考了 Bahdanau Attention，只不过在计算 attention score 的时候，输入从\(h_j\)、\(\textcolor{red}{s_i}\)改成里双向 LSTM 的两个方向的 hidden states

  • Encoder \[ \begin{aligned} \textcolor{blue}{\overrightarrow{h_t}} &= R_{LSTM}(w_t, \textcolor{blue}{\overrightarrow{h_{t-1}}}) \in \mathbb{R}^u \\ \textcolor{red}{\overleftarrow{h_t}} &= R_{LSTM}(w_t, \textcolor{red}{\overleftarrow{h_{t-1}}}) \in \mathbb{R}^u \\ h_t &= \begin{bmatrix} \textcolor{blue}{\overrightarrow{h_t}} \\ \textcolor{red}{\overleftarrow{h_t}} \end{bmatrix} \in \mathbb{R}^{2u} \\ e_{ij} &= w_{s2}^T\mathrm{tanh(W_{s1}h_j)} \\ &= w_{s2}^T\mathrm{tanh([W_{s1}[:u]\quad W_{s1}[u:]]\begin{bmatrix}\overrightarrow{h_j}\\\textcolor{red}{\overleftarrow{h_j}}\end{bmatrix})} \\ &= w_{s2}^T\mathrm{tanh}(W_{s1}[:u]\cdot \textcolor{red}{\overleftarrow{h_j}} + W_{s1}[u:]\cdot \textcolor{blue}{\overrightarrow{h_j}}) \\ \alpha_{ij} &= \frac{e_{ij}}{\sum_{k=1}^T}, \alpha_{ij}\text{ is a scalar} \\ m_i &= \textcolor{yellow}{c_i} = \sum_{j=1}^T\alpha_{ij}\textcolor{blue}{h_j} \end{aligned} \] 从公式明显可以看出，Self Attention 计算 Score 的设计明显是参考了 Bahdanau Attention 的计算方法。

上面的计算是单个 Attention 的计算方法。然后借鉴一下卷积网络的多个 kernel 的思想，作者设计了多个 Attention，期望不同的 Attention 学习到不同的注意力，从而更好的提取特征。

这种一个不行就上多个到方法在深度学习中经常使用，比如 CNN 多 kernel， MultiHead Attention， Mixture of Experts 等。

基于这个思路，作者提出了 Attention 的矩阵运算形式

\[ \begin{aligned} H = (h_1,h_2, ... ,h_n) &\in \mathbb{R}^{n\times 2u} \\ W_{s1} &\in \mathbb{R}^{d\times 2u} \\ W_{s2} &\in \mathbb{R}^{r\times d} \\ E = W_{s2}\mathrm{tanh}(W_{s1}\cdot H^T) &\in \mathbb{R}^{r\times n} \\ A = \mathrm{softmax}(E) &\in \mathbb{R}^{r\times n} \\ M = AH &\in \mathbb{R}^{r\times 2u} \end{aligned} \]

这其实就是MultiHead了，在公式中是通过\(r\)来体现的。矩阵相乘 \(AH\) 已经和 Transformers 最终形态的Attention \(AV=\mathrm{softmax}(\frac{QK^T}{\sqrt{d}})V\) 有点类似了

随着 head 数量增多后，在具体任务上的表现

后来论文Multi-head or Single-head? An Empirical Comparison for Transformer Training的作者认为，当前的 MHA 的形式，同一层的 Head 之间没有任何关联，想建立关联得到下一层，这样的效果可能不如多层的 Single Head。

通过实验，也确实证明了多层 Single Head 比浅层的 MHA 效果好

那为什么没有流行起来呢？

核心还是 MHA 可以非常方便的并行计算，而采用 Single Head 的话，层与层之间有诸多的非线性操作还有 norm 等，不如 MHA 直接做一些视图变换然后直接矩阵相乘效率高

GQA代码实现

Key 和 Value 在同一个组中被不同的 Query共享。

  • MHA 中 Query, Key, Value 的矩阵的大小为 (batch, n_head, length, hidden_size)
  • GQA 中 Query 的大小保持不变，Key, Value 的矩阵的大小变为 (batch, n_head / group_size, length, hidden_size)

为了实现矩阵的相乘，有两种做法：

方法一

利用广播机制，把 QKV Reshape 成下面的样子：

  • Query: (batch, n_head / group_size, group_size, length, hidden_size)
  • Key: (batch, n_head / group_size, 1, length, hidden_size)
  • Value: (batch, n_head / group_size, 1, length, hidden_size)

这种方法最直观，最好理解，但是需要做一些广播和最终合并的处理,要对 MHA 的代码进行多处修改

方法二

能不能把问题转变成原来的 MHA？

答案就是把 Key 和 Value 进行 repeat，用相同的 Key 和 Value 填充到原来的 MHA 中的 Key 和 Value，这样就把问题转换成 MHA 了。
