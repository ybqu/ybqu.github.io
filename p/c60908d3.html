MCP 是什么？怎么实现的？

发表于2025-08-31|更新于2025-08-31|LLMsAgentMCP / FunctionCall
|总字数:1.3k|阅读时长:5分钟|浏览量:
  • 大概2023年6月，OpenAI 的 API 提供了 function call功能
  • 大概2024年底，在 function call 的基础上，Anthropic 提出了 MCP (Model-Content-Protocol)。

当然在实际的产生调用工具的请求也可以是其他的实现，function call 是目前最常用的模式。MCP 的工作模式其实并不难，用一张图就能说清楚：

MCP 隐藏了很多技术细节，让开发者只需要调用一次 API，就能访调用多种工具来实现自己的功能。而这里面最重要的就是 Function Call。

Function Call 流程和原理这个function call功能流程如下（这里以调用python为例，实际上可以是任何语言或者api）：

  • User->ChatGPT：提供给ChatGPT一些函数，每个函数要写清楚函数的名称(name), 函数的作用(description)和参数(parameters)。并且问ChatGPT一个问题
  • ChatGPT->User：ChatGPT会判断需不需要调用你提供的函数。如果判断你提供的函数可以解决你的问题，会将你的问题转化为设置好参数的函数。在对话系统的小模型时代，相当于做了个NLU意图分类 + text2code
  • User->ChatGPT：根据ChatGPT的给出的函数，自己运行函数，然后把函数运行的结果返回给ChatGPT
  • ChatGPT->User：ChatGPT根据之前的对话信息和你给的结果，最终将回答问题

看到这里就会发现整个流程其实非常像一个only-one-job的HuggingGPT，只不过HuggingGPT是调用模型，这里是调用函数。

如果你自己搞一个函数的pipeline，其实就是langchain了

只不过langchain的结构是在函数里与ChatGPT对话来完成任务，而function call是在对话里调用函数。

如果再稍微设计一下prompt，让ChatGPT来自己决策完成任务需要使用哪些函数，其实就跟AutoGPT差不多了
