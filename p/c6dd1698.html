梯度累积的原理和实现

发表于2025-09-10|更新于2025-09-10|LLMsTransformers模型训练
|总字数:1.5k|阅读时长:6分钟|浏览量:

batch size 的大小对于模型的最终效果影响还是比较大的。

  • 设置太小，梯度的方差可能比较大，导致不容易收敛，但是有机会跳出局部最优解
  • 设置太大，训练稳定、效率高，但是有时候陷入到局部最优出不来了，导致泛化能力下降，尤其是样本不太均衡，某一类样本占主导地位的时候

假设我们现在资源有限，模型很大，训练的时候 batch size 只能设置成 1。这么小的 batch size 显然不是我们所期望的，但是再大显存就要 OOM 了。因此梯度累积就诞生了。

大的 batch size 训不起，分期训，一次只训练一部分，攒够了 batch size 的 梯度之后，再进行更新

Gradient Accumulation 原理

从数学上来讲，使用梯度累积后的梯度和不使用梯度累积的梯度是完全等价的。

因为最终 loss 的值就是一批 batch 中所有样本单独 loss 的和，再取平均。只要数据一样，loss 就一样，loss 一样，算出来的梯度就一样。

假设\(X = {x_1, x_2,..., x_n}, y = {y_1, y_2,..., y_n}\)

  • 不使用梯度累积的 loss 为 \[L = \frac{1}{n}\sum_i^n\text{CrossEntropy}(F(x_i),y_i)\]
  • 假设使用梯度累积，这批数据分成 m 个批次，则每个批次有 n/m 个样本。则 loss 为： \[ \begin{aligned} L^{\prime} & =\frac{1}{m} \sum_{i}^{m} L_{i} \\ & =\frac{1}{m} \sum_{i}^{m}\left(\frac{1}{n / m} \sum_{j}^{n / m} \operatorname{CrossEntropy}\left(F\left(x_{j}\right), y_{j}\right)\right) \\ & =\frac{1}{m} \frac{1}{n / m} \sum_{k}^{n} \operatorname{CrossEntropy}\left(F\left(x_{k}\right), y_{k}\right) \\ & =\frac{1}{n} \sum_{k}^{n} \operatorname{CrossEntropy}\left(F\left(x_{k}\right), y_{k}\right)=L \end{aligned} \] 可以看出，使用梯度累积并不会影响最终 loss 的值。对于梯度也是类似 \[ \begin{aligned} \frac{\partial L^{\prime}}{\partial X} & =\frac{1}{m} \sum_{i}^{m} \frac{\partial L_{i}}{\partial X} \\ & =\frac{1}{m} \sum_{i}^{m}\left(\frac{1}{n / m} \sum_{j}^{n / m} \frac{\partial L_{j}}{\partial X}\right) \\ & =\frac{1}{m} \frac{1}{n / m} \sum_{k}^{n} \frac{\partial L_{k}}{\partial X} \\ & =\frac{1}{n} \sum_{k}^{n} \frac{\partial L_{k}}{\partial X}=\frac{\partial L}{\partial X} \end{aligned} \] 根据这一点，我们可以在 backward 之后不将梯度归零，来实现梯度的累加。

Gradient Accumulation 实现

正常的一次迭代如下，每个 batch 都会进行梯度更新。

这里需要注意的是梯度清零操作，如果不清零，则每个 batch 的数据计算的梯度会累加到 weights.grad 中，这也是 pytorch 能够很方便的实现梯度累加的一个前提条件。

如果采用梯度累积，则在每个 batch 结束的时候并不更新权重，而是迭代几个 batch 之后才更新。

Transformers 的 BUG

transformers 有个著名的 bug 就是梯度累积的错误计算。这个 bug 在 Dec 6, 2021 被人发现（https://github.com/huggingface/transformers/issues/14638） ，直到 Oct 18, 2024 才被解决(https://github.com/huggingface/transformers/pull/34191)

这个 bug 出现的原因，其实是 sft 的时候会 ignore 一些 label，这就导致梯度累积的 loss 和 没有梯度累积的 loss 不一致。

比如现在有 N 条 sft 的数据。由于 sft 的时候，prompt 部分不参与 loss 的计算，而且 prompt 长度并不相同。假设第 \(i\) 条数据 的 loss 为 \(L_i\)，参与 loss 计算的 token 有 \(m_i\) 个。
则没有使用梯度累积的 loss 为： \[L=\frac{\sum_i^NL_i}{\sum_i^Nm_i}\]

pytorch 的交叉熵损失实现如下： \[\ell(x, y)=\left\{\begin{array}{ll} \sum_{n=1}^{N} \frac{1}{\sum_{n=1}^{N} w_{y_{n}} \cdot 1\left\{y_{n} \neq \text { ignore\_index }\right\}} l_{n}, & \text { if reduction }=\text {mean} \\ \sum_{n=1}^{N} l_{n}, & \text { if reduction }=\text {sum} \end{array}\right.\] 默认采用的是 mean，也就是取平均，这就导致不同长度的 prompt 在默认的使用 mean 的交叉熵损失时，loss 不一样了。
如果每次只累积一条样本，则 loss 变成了 \(L'=\sum_i^N\frac{L_i}{m_i}\)
很显然，L' 和 L 数学上并不相等

怎么修改呢

把 mean 变成 sum，这样分子就算对了。然后在计算 loss 的时候，除以整个批次参与 loss 计算的 token 数，这样分母也有了，也就和原来的 loss 计算一致了。
